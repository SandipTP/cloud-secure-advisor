I. Identity & Access Management (IAM) - The #1 Attack Vector
Root account used for daily tasks instead of IAM users.

MFA not enabled on Root account.

MFA not enabled for privileged (Admin) IAM users.

Access keys older than 90 days (not rotated).

Hardcoded credentials in application source code.

Hardcoded credentials in User Data scripts/metadata.

Over-privileged service accounts (e.g., using AdministratorAccess).

Inline policies used instead of managed policies (harder to audit).

Unused IAM users left active (stale accounts).

Unused IAM roles attached to EC2 instances.

Star permissions (resource: *) used in policies.

Publicly assumable IAM roles (misconfigured Trust Relationships).

Cross-account roles without External IDs (vulnerable to Confused Deputy).

Lack of Permission Boundaries on developer roles.

Passwords without minimum length or complexity requirements.

No password expiration policy.

Access keys enabled for users who only need Console access.

Identity Providers (SAML/OIDC) configured with weak trust.

Lack of Session Tags for temporary security credentials.

Root account has active Access Keys (Major risk).

II. Storage & Data Management (Data Leaks)
S3 buckets with public read access via ACLs.

S3 buckets with public write access (allows malware hosting).

S3 buckets without Default Encryption enabled.

S3 Versioning disabled (no protection against accidental deletion).

S3 logging disabled (cannot see who accessed data).

EBS snapshots made public (entire drive visible to the world).

EBS volumes unencrypted.

RDS snapshots made public.

RDS instances unencrypted.

Azure Blob storage containers set to "Public Access Level."

Google Cloud Storage buckets with allUsers permissions.

Object Lock disabled on critical compliance data.

Lack of Lifecycle policies (retaining sensitive data longer than needed).

KMS keys without rotation enabled.

Overly permissive KMS Key Policies (allowing anyone to decrypt).

EFX/FSx file systems unencrypted.

Publicly accessible Backup Vaults.

Unsigned S3 Pre-signed URLs with long expiration times.

S3 "Block Public Access" disabled at the account level.

CloudFront distributions fetching from S3 without OAI (Origin Access Identity).

III. Networking & Edge Security
Security Groups allowing SSH (22) from 0.0.0.0/0.

Security Groups allowing RDP (3389) from 0.0.0.0/0.

Security Groups allowing all traffic (0.0.0.0/0) on all ports.

Default Security Groups allowing unrestricted internal traffic.

VPC Flow Logs disabled.

Public IP addresses assigned to internal database instances.

Unused Network ACLs (NACLs) left in "Allow All" state.

WAF (Web Application Firewall) not associated with CloudFront/ALB.

WAF in "Detection" mode instead of "Prevention" for known threats.

Lack of VPC Endpoints (forcing traffic over the public internet).

Open MongoDB/Elasticsearch ports (27017 / 9200) to the internet.

Load Balancers using insecure/deprecated SSL/TLS protocols (TLS 1.0/1.1).

Unprotected API Gateways without throttling or auth.

VPC Peering with overlapping CIDR blocks or over-permissive routing.

Direct Connect/VPN connections without encryption.

DNS records (Route53) pointing to deleted resources (subdomain takeover).

No DDoS protection (AWS Shield Standard vs Advanced) for critical apps.

Standard HTTP (Port 80) allowed without redirect to HTTPS.

Inbound traffic allowed from blacklisted IP ranges.

Missing "Internal Only" tags on private subnets.

IV. Compute & Virtual Machines (EC2/Lambda/Containers)
EC2 instances with IAM roles allowing iam:PassRole.

Lambda functions with environment variables containing secrets.

Lambda functions without a VPC (running in the public realm).

Kubernetes (EKS/AKS) Dashboard exposed to the internet.

Docker sockets exposed to containers (Privilege Escalation).

Running containers as "Root" user.

Over-permissive Kubernetes Service Accounts.

EC2 Instance Metadata Service (IMDSv1) enabled (vulnerable to SSRF).

Auto Scaling Groups using outdated, unpatched AMIs.

No resource limits on containers (leads to DoS/Cloud-flogging).

Lambda functions with high timeout values (cost/security risk).

Unencrypted Lambda source code at rest.

Sensitive data in container logs (stdout).

Fargate/ECS tasks with public IP addresses.

EC2 termination protection disabled on critical servers.

V. Logging, Monitoring & Governance
CloudTrail disabled in one or more regions.

CloudTrail log file validation disabled (allows log tampering).

No alarms for "Unauthorized API Calls" (CIS 3.1).

No alarms for Security Group changes.

No alarms for IAM Policy changes.

Config Service disabled (cannot track resource history).

No alerting for Root account login.

Centralized logging bucket is not encrypted.

Lack of tagging (prevents cost allocation and security filtering).

CloudWatch Logs retention set to "Never Expire" (cost) or too short (forensics).

GuardDuty disabled (no automated threat detection).

Security Hub disabled (no central security score).

No automated remediation for known misconfigurations.

Missing "Emergency Access" (Break-glass) account.

No alerts for Console login without MFA.

VI. Modern Services & Miscellanea
WorkSpaces (VDI) with local admin rights enabled for users.

AppStream fleets with internet access and no web filtering.

Cognito User Pools allowing self-registration without verification.

Secrets Manager secrets without rotation enabled.

SageMaker notebooks with direct internet access.

SNS Topics with "Allow Everyone" publish permissions.

SQS Queues unencrypted.

EventBridge buses allowing cross-account events without validation.

Orphaned Snapshots and Volumes (Security risk + Cost).

Lack of Service Control Policies (SCPs) to restrict regions (e.g., preventing resources in non-operating countries).
